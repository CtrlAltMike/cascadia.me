# Cascadia.me CSS audit — July 23, 2026

## Scope

The audit covered every production stylesheet and all 23 registered pages, with particular attention to:

- cascade order and stylesheet ownership;
- exact duplicate declarations;
- retired or unreachable selectors;
- global rules inside page-family styles;
- navigation and shared-frame overrides;
- responsive breakpoints and horizontal overflow;
- stylesheet parsing and runtime loading;
- desktop and mobile behavior across every page family.

## Findings

### The cascade architecture is sound

The production cascade has a clear three-layer structure:

1. `base.css` and `components.css` provide the foundation.
2. Family styles provide distinctive page composition.
3. `design-system.css` and `site-frame.css` load last and normalize shared tokens, primitives, navigation, footer, and sharing UI.

The existing design-system validator already prevents the major page-family styles from taking shared-frame ownership back. No page-family regression was found in that boundary.

### One duplicate responsive block was safe to remove

`components.css` repeated the same mobile navigation declarations at both 1080 and 768 pixels. Because the 1080-pixel rules already apply below 768 pixels, the narrower copy had no effect. The duplicate declarations were removed without changing computed behavior.

### Older selector groups need deprecation, not immediate deletion

`components.css` and `living-watershed-guide.css` retain groups associated with earlier versions of the home, generic guide, and Atlas layouts. Static reachability checks identify many of these selectors as likely retired.

They were not removed in this audit because static class matching cannot prove that a selector is absent from generated, stateful, third-party, print, or future-compatible markup. Removing hundreds of rules at once would offer little user-facing benefit while widening regression risk.

The appropriate next step is a separate deprecation pass:

1. identify one retired component section at a time;
2. confirm no HTML, script, generated state, print surface, or third-party integration uses it;
3. remove that section;
4. compare representative screenshots and run the complete release gate.

### Repeated leaf rules are generally breakpoint contracts

Other exact repeated declarations occur across distinct media queries—for example, reduced viewport heights, narrow phones, print, or reduced-motion modes. Those repetitions preserve explicit breakpoint behavior and were left in place.

### `!important` use is concentrated in justified boundaries

Most production `!important` declarations occur in print rules, accessibility overrides, MapLibre control styling, or tightly scoped instrument layouts. No broad global escalation was found that justified a risky specificity rewrite.

## Regression protection added

The browser suite now visits every page in the central registry in both desktop and mobile Chromium. For each page it verifies:

- local stylesheets are readable and contain parsed rules;
- the shared header, main landmark, and skip-link target exist;
- neither the document nor body introduces horizontal overflow;
- no uncaught page error occurs.

The existing interaction suite continues to exercise the shared share dialog, mobile navigation, Atlas controls, Signals message overlays, the Field Stories shelf, and an individual story.

## Result

No visual redesign was needed. The audit produced a smaller, clearer responsive navigation section; a cache-safe stylesheet release; durable all-page CSS smoke coverage; and a mandatory page-family extension procedure linked through `AGENTS.md`.
