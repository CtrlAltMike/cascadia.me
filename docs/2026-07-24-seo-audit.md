# Cascadia.me SEO audit

Date: July 24, 2026

## Scope

This audit covered all 23 registered production pages, the 22 indexable canonical URLs, the live domain, and representative rendered pages from every major family. It reviewed:

- crawl and index directives;
- HTTPS and hostname consolidation;
- canonical URLs and duplicate URL variants;
- `robots.txt` and `sitemap.xml`;
- titles, descriptions, headings, and internal discoverability;
- Open Graph and Twitter previews;
- JSON-LD structured data;
- image alternatives, dimensions, and `<picture>` fallbacks;
- browser-rendered Lighthouse SEO checks.

Google Search Central was the governing reference:

- [SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
- [Sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- [Canonical URL guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- [Image SEO guidance](https://developers.google.com/search/docs/appearance/google-images)
- [Structured data guidelines](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)

## Findings

The site’s search foundation is strong:

- HTTP redirects to HTTPS.
- `www.cascadia.me` redirects to `cascadia.me`.
- Unknown routes return HTTP 404.
- The custom 404 page is `noindex,follow`.
- Every indexable page has a unique registered title, description, and self-canonical.
- `robots.txt` permits crawling and declares the absolute sitemap URL.
- The sitemap contains exactly the 22 registered indexable canonicals and excludes the 404 page.
- Every indexable page is reachable from Home in no more than two internal link steps.
- All rendered `<img>` elements have alternative text and intrinsic dimensions.
- Every `<picture>` has a crawlable `<img src>` fallback.
- Representative Lighthouse SEO audits scored 100 for Home, Guides, Atlas, Signals, and Field Stories.

Google may choose a different title link or snippet from visible page content. Several descriptions are intentionally detailed; they were not shortened merely to fit an obsolete fixed-character rule.

GitHub Pages also serves `/index.html` and nested `/index.html` URL variants with HTTP 200. The pages’ self-canonicals identify the preferred URLs, which is the available repository-level consolidation mechanism. Redirecting those variants would require a future hosting-layer change.

## Corrections made

- Completed Signals’ search contract with large-image preview permission, site identity, representative Open Graph and Twitter images, image alternatives, and `WebPage` JSON-LD.
- Registered Signals’ required schema type in the common page registry.
- Added `scripts/validate-seo.mjs` to prevent future drift in metadata, crawl directives, structured data, image semantics, sitemap membership, internal discoverability, and crawl depth.
- Added that validator to both `npm run validate` and the GitHub release gate.
- Added the SEO requirements to the page-family extension process and common-framework reference.

These changes do not alter visible page layout or interaction.

## Deliberately deferred

- Bespoke social cards for Signals and individual Field Stories could make shared links more distinctive, but they require visual direction and asset work. Existing representative Cascadia artwork remains valid.
- Hosting-level redirects for explicit `index.html` variants would improve URL consolidation beyond canonical tags, but GitHub Pages does not provide a repository-native redirect rule for this case.
- Search Console coverage, indexing, query, and Core Web Vitals data require access to the site’s Google Search Console property and were outside this repository audit.
